# Нативное ядро — код для будущей интеграции, НЕ готовая версия 0.6

## Что реализовано и проверено отдельно от игры
- Настройки: проверка диапазонов, чтение/сохранение, версия схемы, запрет неизвестных и дублирующихся ключей, запись через временный файл с заменой на Android/Linux.
- Выбор тем: заданный фон/музыка, случайная тема при входе или после боя, независимый случайный выбор музыки; воспроизводимый seed для тестов.
- FPS: вычисление ожидания до следующего кадра, смена лимита, сброс при длинной паузе, защита от обратного хода часов. Сам по себе ограничитель НЕ подключён к рендеру игры и не повышает FPS.
- Контракт применения параметров звука, камеры, качества текстур и частиц. Значения валидируются; изменение картинки/звука выполняет отсутствующий игровой адаптер, не ядро.
- Обработчики событий: запрос пропуска лучшего момента, пропуска анимации награды, повторной игры, выхода в лобби. Повторный запрос новой игры по одному battleId блокируется после подтверждения адаптером.
- Проверка возможностей: при отсутствии адаптера возвращается NO_GAME_BRIDGE. Не поддерживаемые или отклонённые операции НЕ считаются работающими.

## Что НЕ реализовано
Нет адаптера Brawl Stars, точек перехвата, рабочих адресов функций, изменения ресурсов в памяти, игрового меню, подключения к официальным серверам, готового APK или автоматической модификации исходного APK.
Нет скин-чейнджера, смены иконки, эффектов убийства, модели частиц/рендера, скрытия статусов, прокси, разблокировки подписок и начисления ресурсов.
Событие instantReward означает только запрос к адаптеру пропустить анимацию — не выдачу награды и не изменение серверного состояния.
GameBridge в include/modcore.hpp — интерфейс, не реализация интеграции. FakeBridge существует только в tests/ и не должен использоваться в продукте.

## Сборка и проверка на Linux/WSL
Нужен компилятор C++17 (g++). В папке native-core:
```
sh build-test.sh
c++ -std=c++17 -Wall -Wextra -Werror -pedantic -Iinclude src/modcore.cpp src/cli.cpp -o build/modcore_cli
./build/modcore_cli init build/settings.cfg
./build/modcore_cli validate build/settings.cfg
./build/modcore_cli plan build/settings.cfg
```
init не перезаписывает существующие настройки. plan выводит NO_GAME_BRIDGE — это правильное состояние без игры.
Для CMake 3.22+: cmake -S . -B build-cmake; cmake --build build-cmake; ctest --test-dir build-cmake.
CMake-рецепт приложен, но CMake в текущей среде отсутствует и этим способом сборка не проверялась.

## Подготовка к Android NDK
CMakeLists.txt создаёт статическую библиотеку modcore. При кросс-сборке выбрать NDK toolchain, ABI arm64-v8a, API >=26 и MODCORE_BUILD_TESTS=OFF.
Это создаёт библиотеку ядра, НЕ APK. Нужны внешний JNI-модуль, вызовы из жизненного цикла игры и реализация GameBridge для конкретной версии клиента.
NDK и Android SDK в текущей среде отсутствуют: кросс-сборка и запуск не проверены.

## Контракт интеграции
1. Игра/адаптер вызывает Runtime в одном выделенном потоке. Ядро не является thread-safe. GameBridge должен жить дольше Runtime или быть явно отсоединён.
2. Настройки хранить только в приватном каталоге собственного приложения. SettingsStore не является песочницей файлового доступа. Запись рассчитана на одного писателя, без fsync-гарантии переживания отключения питания. Атомарная замена проверена на Linux; на Windows семантика rename отличается.
3. Адаптер самостоятельно подтверждает наличие и безопасность каждой возможности supports(). По умолчанию подключённого адаптера нет.
4. execute() обязан вернуть true только после корректного применения или принятия действия движком. Это не подтверждение серверного результата. Адаптер отвечает за контекст и поток вызова.
5. FramePacer вызывать один раз перед кадром с монотонными наносекундами. Ожидание выполнять только в безопасной точке цикла; нельзя вставлять sleep в произвольный перехват.
6. Перед PlayAgain адаптер подтверждает canQueue и передаёт ненулевой стабильный battleId. История дедупликации хранится на время сессии и сбрасывается при attach().
7. ID ресурсов из theme-identifiers.json извлечены из присланного CSV. Наличие файлов и совместимость с выбранной версией игры не проверены. Никакие игровые ресурсы не включены.
8. Данные GameBridge и все события должны поступать из реального движка, не из таймера/тестового адаптера.

## Проверки
154 проверки прошли обычной сборкой g++ с -Wall -Wextra -Werror -pedantic.
Проверены: настройки, числовые границы, повреждённые конфиги, выбор тем, дедлайны кадров, отсутствие адаптера, отклонение возможностей, события и дедупликация.
Это модульные проверки с тестовым адаптером, не тесты в игре.
UBSan проверить не удалось: отсутствует библиотека libubsan. Утверждения об успешной sanitizer-проверке нет.

## Отношение к плану 0.1–0.6
0.1: сборка/установка изменённого клиента не выполнены.
0.2: собственный код в игру не подключён.
0.3: прежнее браузерное меню остаётся отдельным прототипом, не интерфейсом внутри игры.
0.4: реализован выбор ID тем; применение фоновых/музыкальных ресурсов не реализовано.
0.5: реализованы расчёты FPS и контракты параметров; вызовы из реального рендера отсутствуют.
0.6: реализованы решения по событиям; реальные игровые вызовы отсутствуют. Скин-чейнджер и эффекты не реализованы.
Следовательно, этот архив нельзя называть рабочим релизом 0.6.
