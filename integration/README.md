# Встраивание в процесс игрового клиента

Это отдельный путь сборки, НЕ прежнее приложение-меню.

## Что действительно делает код
- Распаковывает полный исходный APK через apktool, не декодируя игровые ресурсы.
- Находит указанную игровую Activity и проверяет её цепочку наследования.
- Встраивает вызов `khc.integration.Menu.attach(Activity)` в onResume (или добавляет безопасное переопределение).
- Собирает наше Java-меню в отдельный DEX и добавляет его в тот же APK.
- Пересобирает, выравнивает и подписывает тестовым ключом.
- При запуске игры Android-меню должно добавляться к окну самой игры через addContentView. Отдельное приложение или разрешение SYSTEM_ALERT_WINDOW не используется.

В меню реализованы реальные Android-функции окна: изменение яркости окна и KEEP_SCREEN_ON, а также возврат исходных значений. Это не управление боевыми функциями, не камера движка и не скин-чейнджер. Прежний C++ GameBridge здесь не подключён.

## Входной файл
Нужен ПОЛНЫЙ standalone APK, не ZIP с извлечёнными библиотеками, не XAPK/APKM, не страница Telegram.
Источник задаётся в integration/source.json или полями ручного запуска Actions.
Поддержаны публичная HTTPS-ссылка на файл и публичная ссылка на файл Яндекс Диска (API получения download URL).
Папка Яндекс Диска не подходит. Файл остаётся доступен сборщику на GitHub, скачивание в чат не требуется.
SHA256 рекомендуется сравнить с исходным APK. Если хеш не указан, сборщик только вычисляет его, но не подтверждает подлинность файла.
Оригинальные игровые файлы и ключ подписи в Git не добавляются.

## Состояние проверки
Локально прошли 12 тестов Python для патчера и обработки входных данных.
CI должен дополнительно скомпилировать меню и проверить полный цикл на нашем минимальном тестовом APK. Такой успех НЕ означает проверку на настоящем Brawl Stars.
Без URL в source.json настоящая игровая сборка пропускается: зелёный статус относится только к тестовому конвейеру.
На момент написания Android-меню визуально не проверено: нет запущенного Android-девайса/эмулятора. Не заявляется ни успешный запуск на vivo, ни корректное отображение поверх рендера Brawl Stars.

## Ограничения и риски
- Изменение APK меняет подпись. Проверки целостности, загрузчик мода, ресурсы или официальный сервер могут отказаться работать. Инструмент не отключает проверки защиты и не гарантирует совместимость.
- Патчер прекращает работу при дублирующихся DEX-классах, неясном наследовании, нативном/абстрактном lifecycle или финальном методе предка вместо попытки угадать.
- Подпись тестовая и меняется между запусками. При том же package name Android не установит APK поверх официального клиента с другой подписью. Не удаляйте основной клиент без сохранённого доступа к аккаунту; испытания лучше проводить на отдельном устройстве/профиле.
- Выравнивание ZIP на 16 КБ не исправляет неподходящую ELF-компоновку исходных библиотек. Совместимость Android 17 должна проверяться на устройстве.
- Присланная база BSD сохранит функции её авторов, если продолжит запускаться. Это НЕ означает, что мы самостоятельно реализовали эти функции или получили права на их код/сервисы.
- Игровые ресурсы/платные возможности не разблокируются. Аккаунты и сетевой протокол не изменяются.
- Сборка больших APK требует свободного места, времени и квоты GitHub Artifacts. Размер полного файла должен быть <=4 ГиБ; лимит хранения артефактов может быть ниже.

## Структура
java/ — собственное встраиваемое Android-меню.
patch_lifecycle.py — точечный, идемпотентный smali-патчер.
compile_helper.sh — javac + D8.
integrate.sh — сборка на базе исходного клиента.
build_fixture.sh — проверка упаковки на собственном тестовом приложении.
source.json — выбранная база (сейчас URL пуст).
